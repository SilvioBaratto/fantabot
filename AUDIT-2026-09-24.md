### 0.1 `rules_for_lega` drops `max_roles` on the Mantra path **[re-verified]**
`src/fantabot/domain/asta/state.py:137-146`

`max_roles` is read **only inside `if classic:`**. The Mantra return builds
`RosterRules(size, min_goalkeepers, min_movement)` — and `RosterRules` has no field for it
at all (`['size','goalkeeper_roles','min_goalkeepers','min_movement']`).
`max_goalkeepers()` is derived as `size - min_movement`.

Measured against lega 4103937's live snapshot:

    rules_for_lega(role_groups=2, roster_size=32, min_roles=[2,23], max_roles=[4,28])
      max_goalkeepers() -> 9     lega declares maxrl[0] = 4
      max_movement()    -> 30    lega declares maxrl[1] = 28

Consumers, both fail-open: `optimizer.py:360` (hard ceiling on drafting a keeper) and
`reservation.py:150` (the walk-away). Nothing catches it — not `max_bid`, not `lot_ceiling`,
and per `docs/fantalab/01:142` not the server: the MAX cap is client-enforced.

This is the 2026-09-02 roster-rules drift CLAUDE.md:261-271 recorded. `rules_for_lega` was
taught to read `minrl` and never `maxrl`.

Invisible to the suite: `tests/domain/asta/test_asta_rules_for_lega.py:50-56` passes
`max_roles=[4, 28]` and asserts nothing about it.

### 0.2 `because(exc)` 500s on any empty-message exception **[re-verified]**
`app/fantabot_app/api/outcomes.py:141`, mirrored at `api/v1/endpoints/room.py:79-82`

`exclusions.py:133`, `room.py:120,131`. The only test passes a 3-line message.

## Tier 5 corrections, and the decisions it left open

### The audit was wrong once more, and this one would have cost money
It calls `asta_calibrate.py:202-216` and `asta_room.py:600-618` "the ceiling computation,

### Left duplicated on purpose, with the reason now in the code
- **The per-call `bid_writer` lambda.** `test_asta_arming.py` *discovers* the live commands
  by matching an `ast.Lambda` containing a call to `bid_writer`. Any helper that returns the
  writer stops being a lambda, `LIVE_COMMANDS` becomes `[]`, and three test classes silently

- **`_timed_journal` / `_timed_read`.** `test_asta_cycle_ms.py` asserts exactly two

- The `stop_poll` keyword block and the dry-run banner, both pinned by AST tests that exist
  to stop either body re-deciding.

### Declined during Tier 5, then **made 2026-09-24** in commit `a61fbe2`
All five below were done on the owner's instruction. Two notes that outlived the decision:

- **The `health()` narrowing was wrong on its first attempt, and wrong by not measuring.** It
  classified failures by SQLSTATE; psycopg2 attaches none to a connection error, so `pgcode`
  is `None` for a missing database, an unknown role and a refused connection alike, and every
  failure answered `unreachable` — an affirmative false claim where `(False, latency)` had
  claimed nothing, and one whose printed remedy sends the operator to the thing that works.
  Rewritten to read the driver's message and to answer `None` when it recognises none.
- **The classification fires almost nowhere on its own.** A connection failure happens inside
  `get_session()` and never reaches `SELECT 1`, so `db check`'s outer handler catches it
  first. That handler now reads the same names — and stopped rendering the DSN with
  `render_as_string(hide_password=True)`, which was the **third** site of the defect
  `safe_dsn` exists to fix, missed when the two login preflights were repaired.

### The decisions as they stood
1. **`asta calibrate`'s `--format` refusal.** Both mechanisms exit 2, but the other three
   raise `typer.BadParameter`, which Click renders on **stderr**; calibrate prints to
   stdout. A cron or app wrapper capturing stdout would stop seeing the line. Calibrate also
   legitimately rejects `""` where the others read it as "detect", because it names a
   *corpus*, not a room.
2. **Giving `quotazioni` the retry** the other two scrapers have. One request per season
   against 38 and 3 — the asymmetry may be deliberate and has never been measured. The whole
   change is now one line, and both arguments are in `_site.fetch_once`'s docstring.
3. **`synchronize.ts` dropping the crashed child's own words.** One line
   (`error: this.scrapeError`). The user would see `"ConnectError: ..."` where they now read
   a reassuring generic sentence — which is the point, and is why it is a decision.

## Residuals after Tier 1 — declared, not closed

Each of these is a boundary a guard states about itself rather than a gap nobody noticed.
They are recorded so the next pass does not mistake them for oversights.

- **The taint hole.** `x = token; print(x)` is not decidable from syntax. `CREDENTIAL_RETURNING`
  is a ratchet over six functions whose return is a credential, and the secrecy file says
  plainly that this is the one shape it does not claim to have shut.
- **`except (*FAMILIES, Exception)`** — a starred handler display. Ruff misses it (verified) and
  the decision-route ban covers only routes importing `api/outcomes.py`. Realistically nobody
  writes it; recorded because it was measured.
- **Dynamic dispatch in the `dbdata` walk.** `helper()`, `self.method()` and
  `from conftest import helper` are followed; `module.helper()` and a callable passed as a
  parameter are not. Closing it needs name binding, not an AST walk.
- **`model_copy` attribution.** `helper().model_copy(update={"outcome": ...})` cannot be
  attributed to a model. Covered generically one level up: every `outcome` literal in a route,
  by any shape, is compared with `==` against the union of the per-model scans, so such a site
  fails the suite rather than disappearing from a pinned tuple.
- **The library and the app now disagree about `BLE`.** The app enforces what the library
  argues in prose at `repositories/admin.py`, `http/fantalab/room.py` and `harvest/stream.py`.
  Migrating the library is `+BLE` plus three `noqa`s carrying comments that already exist.
  Until then, CLAUDE.md's "same `select`/`ignore` as mailwise" describes neither config —
  **CLAUDE.md was deliberately not edited from inside these tasks.**
- **`line-length = 100` in both packages is enforced only through isort's wrapping**, since
  `E501` sits in the inherited `ignore`. True before this work; now true visibly.
